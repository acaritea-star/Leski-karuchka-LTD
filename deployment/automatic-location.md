# Remembered location and shared GPS

Location preference is stored under `leski:auto-location:<profile id>` on the current device. Only `on`/`off` is persisted, never coordinates. Storage failures fall back to session memory. Explicit off wins over previously granted browser permission; a new explicit GPS/Online action can turn it on again.

Customer home checks browser permission after request recovery. Granted permission can initialize an unset preference; the first visit with an undecided permission never automatically opens a prompt. A saved on resumes acquisition on opening, subject to browser permission. One fresh, precise Bulgaria fix fills an unselected pickup once. Manual selections and late asynchronous GPS/geocoding responses are guarded by a revision. Later movement does not move selected addresses or request new fare/route calculations. Live fixes remain in browser memory; customer fixes are not written to the database.

`sharedGps.ts` owns one watch across driver dispatch and navigation, plus a deduplicated fresh one-shot read for explicit activation and idle heartbeats. Navigation receives a recent shared fix immediately. An offline driver with remembered/granted permission can read one local fix to center the map without uploading it. The decorative driver map observes this state and does not independently request location. Driver database cadence remains 5 seconds while moving and 15 seconds for a fresh stationary heartbeat, with the existing 45-second dispatch freshness requirement, 100m accuracy ceiling and Bulgaria check. No new library or database schema is added.

Settings live in customer Settings and driver Profile. Turning off clears GPS memory, invalidates pending reads, releases the native watcher and stops the driver heartbeat. The driver's authoritative status is read and, if online, updated to offline. The active trip is not cancelled. If that server operation fails, the UI reports the lack of confirmation and provides a retry; it does not falsely show a successful server update. A write already sent before turning off cannot be unsent. Existing server freshness checks exclude stale drivers after 45 seconds.

Logout/account changes clear location memory. Other-tab preference changes propagate through the storage event. Browser permissions remain separate: temporary grants, cleared site data, private browsing and OS decisions may cause another system prompt. A remembered preference does not bypass denied permission. Closed, hidden or locked-phone web apps cannot guarantee background GPS; keep the driver page visible during work.

Validation: lint, TypeScript, production build and Vitest, including single-watch leases, fresh-read deduplication, pending-read cancellation, per-user preference, other-tab off, offline failure/retry, customer auto initialization, explicit off, first-visit prompt avoidance, manual pickup protection and late geocoding after off.
